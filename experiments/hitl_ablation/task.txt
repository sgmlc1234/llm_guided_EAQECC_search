Develop a Python search program for binary entanglement-assisted quantum codes.
This pipeline accepts research ideas from a human, uses model-generated programs
and execution feedback to develop them, and verifies the resulting constructions.
This experiment asks whether iterative feedback helps turn a shared research idea
into an effective program. It reconstructs known feasible parameters; it does not
claim new discoveries.

SHARED RESEARCH IDEA: Instead of maintaining and mutating a basis of S of rank
n-k+c, consider maintaining and mutating a basis of its symplectic dual L of rank
n+k-c throughout the search. For these training cells L has only four vectors.
Convert each candidate L to S with E.nullspace([E._J(v,n) for v in L],2*n) when
calling the exact evaluator. Merely constructing L once and subsequently mutating
S is different from searching in L throughout. This changes the representation
and local neighborhood, not the set of possible codes. Decide how to implement
and improve this idea using rank checks, signature penalties, mutations and
restarts. The same suggestion is provided to every proposal in both policies.
No successful witness, family formula or working L-side search code is supplied.

Define search(target, max_evals). E, np and rng are supplied. Target contains
q=2,n,k,c,d and is read-only. Each target and seed runs in a separate sandbox.
There is NO controller initialization; all success must come from your program.
Use while E.remaining. E.evaluate(gens) consumes one allowance even for invalid
inputs. Integers encode bit 2*i=X, bit 2*i+1=Z. The result includes n,s,c,iso,k,d,
offending,logical_count; malformed inputs or wrong signatures carry error.
For signature mismatches, numeric c/offending fields may still be useful for
repair; d can be None. A solution must have matching k,c and offending=0.
The controller stops immediately on a verified solution and retains the best
valid candidate otherwise. Return None, or return one generator list whose
verification also consumes the SAME quota; no extra free evaluation is allowed.

Helpers: E.gf2_basis, E.nullspace(rows,nbits), E._J(v,n), E.sform(a,b,n),
E.random_stabilizer(n,s,rng), E.span_array, E.symplectic_weights.
E.nullspace computes binary orthogonality; E._J swaps X and Z bits.
E.incumbent and E.incumbent_parameters return copies of the best valid candidate
and its measurements observed within this execution. Initially they are None.
Helpers do not consume evaluator calls, but remain within CPU/memory limits.

Selection prioritizes the mean normalized area under the success-versus-calls
curve: on success at call h with budget B, utility=1-h/B; on a miss it is zero.
Tie-breakers are mean success fraction, then mean clipped distance ratio.
Training feedback contains calls, success, distance and errors, not witness
matrices. Validation/test data are withheld throughout generation. The supplied
starting code is the current selected parent for this proposal. If a recent
attempt is supplied, it may have been rejected; use its feedback accordingly.

Allowed imports: math,itertools,numpy. Use rng, not an unseeded random source.
Module-level code may contain imports, functions and docstrings only. No files,
network, processes, reflection, classes, global declarations or module attribute
mutation. No time module. Use at most 20,000 source bytes and preferably <150
lines. Each target has 120 CPU seconds soft,125 hard,135 wall,1 GiB RSS. Helper
work is included in these limits. Return JSON with one string field code holding
the complete source, without markdown or external dependencies.
